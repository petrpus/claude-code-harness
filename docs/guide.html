Why it exists

Autonomy rots quality unless something holds the line.

Long agent runs fail in two predictable ways: the context window fills with noise until the model drifts, and the model quietly cuts corners to look "done". This harness answers both — state lives on disk so every iteration starts with a clean context, and no iteration counts as finished until an independent, machine-checked gate says so. Cost is a first-class constraint, not an afterthought.

Fresh context, always

Each loop iteration is a new claude -p session. The plan, memory, and feedback live in tmp/autopilot/ — the window never grows, so it never rots.

Gates the model can't fake

The runner re-runs verify itself, scans the diff for secrets, and sends a cheap adversarial verifier to hunt for shortcuts. Self-reported "done" is never trusted.

Cheap where it can be

Haiku verifies, Sonnet builds, Opus plans. Budgets, caps, and a per-phase spend log keep a run from quietly getting expensive.

Agents

Independent reviewers, each pinned to the cheapest model that fits the job.

code-reviewer · sonnet verifier · haiku

code-reviewer reads a diff cold and applies a correctness checklist before PR. verifier is autopilot's adversarial gate — it assumes the diff is broken and hunts an 11-shortcuts list, returning a fail-closed JSON verdict.

Hooks stdin JSON · exit 2 blocks

Shell guards fired around tool calls. All parse tool input as JSON on stdin via hooks/lib.sh (jq-only, fails open without it).

  • pre-edit — blocks .env + lockfile edits block
  • pre-bash — push-from-main, force-push, broad rm -rf block
  • pre-commit-gate — stale/red verify warn
  • inject-git-context — branch/dirty/verify into context
  • on-stop + session-log — reminders + JSONL log

Verify & verification tiers

The harness has its own gate, scripts/verify.sh — check-consistency + a stdin-JSON hook test matrix + a bash -n floor — run before every PR and by autopilot as its machine-verify. Verification is reminders by default (the Stop hooks always exit 0); for unattended runs you can opt into a hard gate, templates/require-verify-before-stop.sh, which blocks the turn (exit 2) until verify is a fresh ok. Opt-in only, never wired by default (ADR-0002).

Typical workflows

Pick the path that matches the situation.

The skills interlock into a few well-worn routes. Each starts from a real situation and names the exact commands, in order.

A) New feature, from a rough idea

Idea → PRD → issues → shipped

Turn a fuzzy request into a sharp spec, then vertical-slice it into issues and implement one at a time with review + verify.

  • /start-feature — grills the plan, writes a PRD, splits it into issues, triages them
  • /next — surfaces the highest-priority ready issue
  • /implement-issue — plan → scaffold → TDD build → code-reviewer → verify → PR

B) A bug, reproducible or not

Diagnose before you fix

Resist the guess-patch loop. Reproduce, minimise, form a hypothesis, instrument, then fix behind a regression test.

  • /diagnose — structured reproduce → minimise → hypothesise → instrument → fix
  • /tdd — lock the fix with a failing-first regression test
  • /commit-agent — policy-gated commit on a feature branch

C) Long, unattended work

Hand it to autopilot

For multi-step work with clear acceptance criteria that should run without a babysitter — safely, on a budget.

  • /project-infra verify — ensure an objective gate exists
  • scaffold tmp/autopilot/PROMPT.md from a PRD or issue
  • loop.sh --budget-usd 10 — gated fresh-context loop until done

D) Onboard an existing repo

From zero to harnessed

Give a project the infrastructure the harness assumes — verify script, CI, devcontainer, env template — in one pass.

  • /harness-init — baseline settings, tmp/, gitignore
  • /project-infra all — verify wrapper, .env.example, CI, devcontainer
  • /harness-doctor — flag stale local copies & missing jq

E) Keep spend under control

See it, then shrink it

Cost awareness is a habit the harness makes concrete: measure, then apply the doctrine.

  • /usage-report 7 — spend by day & model (ccusage + run logs)
  • /cost-discipline — context budget, tool restraint, cheap-model fanout
  • loop.sh --budget-usd — hard ceiling on autonomous runs

F) Documentation that stays true

Generate from the code

Docs drift when hand-written. Derive them from the source and re-check in CI.

  • /openapi-sync — docs/api/openapi.yaml from routes; --check drift in CI
  • /code-map — offline HTML module/dependency map
  • /worklog 7 — a human digest of the week's commits + sessions

Autopilot · the loop engine

Every iteration passes four gates or it doesn't count.

A run is a loop of fresh claude -p sessions. The build phase does exactly one plan item; then the runner — not the model — enforces the gates in order. Any failure writes feedback, resets the sentinel, checkpoints WIP, and feeds the next iteration. The same failure twice triggers one replan; three times aborts.

Caps

iterations, wall-clock minutes, and a --budget-usd hard ceiling; every claude -p wrapped in a per-call timeout.

Safety

refuses main or a dirty tree; never --dangerously-skip-permissions; hooks fire in headless mode too.

State on disk

PROMPT · PLAN · MEMORY · FEEDBACK · status.json · run-*.jsonl · lock under tmp/autopilot/.

Observable

one JSONL line per phase — model, duration, cost, tokens, verdict — read by /usage-report.

Model policy

Plan once smart. Build competent. Verify cheap and often.

Model choice is a cost lever, not a quality compromise: verification is better done by a skeptical cheap model run many times than by one expensive pass. Tiers are pinned in agent frontmatter and in the loop's defaults, and every phase is overridable per run.

Best practices

The disciplines the harness makes easy — use them.

The tooling only pays off if the workflow around it holds. These are the habits the skills, gates, and hooks are built to reward.

01

Spec before code

Drive work from a PRD (/to-prd) or an issue with acceptance criteria. Autopilot's PROMPT.md requires it — it's what the verifier checks "done" against.

02

Test-first, always

Red-green-refactor via /tdd. A behavior change with no test is a shortcut the verifier flags — treat it as a failure, not a nag.

03

Record decisions as ADRs

An architectural call gets a docs/adr/ entry. Cheap to write, expensive to reconstruct later; the gate expects one when the shape changes.

04

Feature branches, real gates

Never commit to main — the pre-bash hook enforces it. Keep an objective verify command green; it's the gate the whole harness leans on.

05

Budget the autonomy

Set --budget-usd and caps on every long run. Prune MEMORY.md, read only what the task needs, fan cheap models out — that's /cost-discipline.

06

Verify independently, then secure

Let a cheap adversarial verifier check the build, and run /security-review before a PR. The loop's secret scan is a floor, not a full audit.
